## 2026-09-24 amendment — current state and revised order

The original diagnosis remains useful, but its execution order is obsolete. Phase 0 is implemented
(`RESULTS.md`), the GPU path is parity-tested and live, and the compiled ring-credit path is adopted.
The first 30k GPU continuation was statistically neutral on all three CE rulers while hot dimensions
grew from 57 to 115. The project still has no direct long-horizon continual-memory/forgetting test.

**Current authority:**

- Measurements: `RESULTS.md` and `docs/optimization/OPTIMIZATION_TEST_STATUS.md`.
- Performance work: `docs/optimization/GPU_OPTIMIZATION_PLAN.md` (executed; read its measured outcome first).
- Cloud execution route: `docs/plans/PLAN-2026-09-23-GPU.md`.
- mini-AGI lessons: `../THINGS-TO-LEARN-FROM-MINI-AGI.md`.

**Revised science queue:**

1. **Telemetry and ruler:** add fixed-shape group/per-dimension GradSNR, actual parameter movement,
   state activity, eligibility use, bytes, and optimizer steps. Do not infer liveness from sigma alone.
2. **Continual-learning probe:** from one common checkpoint, run massed-domain and interleaved-control
   probes at 0, 0.5M, 1M, 2M, and 4M bytes, using the same held-out bytes at every point.
3. **Role-specific LR A/B:** test shared-weight and decay multipliers with an element-wise LR mask first;
   do not add separate beta values in the first experiment. A global-LR arm is required because the
   independent mini-AGI replication found that slowing all parameters can work as well as slowing only
   the trunk.
4. **Memory formation:** judge decay LR with GradSNR, half-life histograms, state RMS, and long-range
   probes, not CE alone.
5. **Spread reinitialization only after liveness telemetry:** reinitialize dimensions proven dormant by
   gradient, movement, state activity, and use. A small capped spread A/B may follow; write/read gates
   and routed memory slots are later architecture work.
6. **Plasticity control only after the ruler improves:** no automatic LR changes while the clean
   in-domain estimate has one primary held-out source and coarse uncertainty.

This amendment corrects the earlier plan's assumption that `--decay-init spread` was the immediate
"big architectural lever." It is now a controlled later experiment, not the next default.

## Phase 1 — Experiment D: data content (overnight, ~8 h)

**Question:** does the corpus *cap* the memory the model can learn?

**Hypothesis:** long-memory dims grow when the data has long-range dependencies. Wikistories
is encyclopedic (weak >8 B structure); narrative prose (Gutenberg novels, already in `data/`)
has paragraphs of coherence — poly better training for long half-lives.

**Design — everything identical except the corpus:**
  - Arm W: wikistories subset (~20 MB, modern clean subset)
  - Arm N: Gutenberg novels (~20 MB; upsampled/repeated if short — record that)
  - Same init (`--seed` fixed), same batch=1024, same steps, same decay init (current default,
    NO spread yet — isolate the corpus variable)

**Measure:**
  - Held-out CE, in-domain AND cross-domain (each arm eval'd on both)
  - Memory histogram: count of dims with half-life >4 B / >8 B / >16 B / >32 B
  - Top-5 σ dims
  - Chat probe (3 fixed prompts, same temperature): does it hold a topic across a sentence?

**Decision rule (amended):**
  - N grows materially more long dims **and uses them in state/long-range probes** ⇒ corpus is part
    of the constraint ⇒ keep a mixed corpus as an arm. Do not make it default until the forgetting
    probe and liveness telemetry agree.
  - N grows only in half-life but not state activity/use ⇒ sigma changed, memory did not.
  - N ≈ W ⇒ content is not the demonstrated limiter ⇒ run the role-specific LR/GradSNR matrix before
    spread or capacity changes. Do not jump directly to Phase 2.

**Cost note:** throughput ~700 B/s–1.5 kB/s ⇒ 20 MB ≈ 5–8 h/arm. Two arms = two nights, or
run sequentially. Do not run two B=1024 trainings concurrently on this box (CPU thrash).

## Phase 2 — the timescale spread (DEFERRED until optimizer/liveness/forgetting gates pass)

**Idea, not yet authorized:** instead of every dim starting at σ≈0.5 (1-byte memory) and drifting,
*seed a power-law spectrum of half-lives* so every scale has a candidate specialist from step 0.

**Gate before implementation/run:** a spread arm may start only after GradSNR, actual parameter
movement, state activity, and eligibility-use telemetry identify the proposed targets as genuinely
dormant. Sigma/half-life alone is insufficient. Start with a small capped A/B; do not assign a broad
long-lived population to the live model by default.

**Hard constraint — tail cost ∝ number of hot dims.** At K=18, hot ⇔ σ^18 > 0.01
⇔ σ > 0.774 ⇔ half-life > ~2.71 B. A *uniform* log-spread over 8,192 dims would make
thousands hot ⇒ GBs of EMA ⇒ dead. **The long end must be sparse.**

**Design — per layer (512 dims), cumulative:**

| target half-life | dims/layer | σ ≈ | tail status |
|---|---|---|---|
| 0.5–1 B  | ~340 | 0.25–0.50 | cold |
| 1–2.5 B  | ~120 | 0.50–0.64 | cold |
| 3–5 B    | ~35  | 0.71–0.76 | cold (just under 1%) |
| 6–10 B   | 6    | 0.77–0.87 | **hot** |
| 12–20 B  | 2    | 0.88–0.94 | **hot** |
| 24–40 B  | 1    | 0.955–0.98 | **hot** |

→ ~9 hot dims/layer × 16 layers ≈ **145 hot dims** ≈ 150 MB tail at B=1024, ~10% step cost. Acceptable.

**Refinement:** bias long dims toward the layers that empirically grew them (1, 6, 12, 14 —
layer6 owns the top-2). Same long population, fewer hot dims ⇒ cheaper tail.

**Implementation:**
  - `--decay-init spread` in Model init
  - a targeted re-init that touches ONLY the ~8,064 dormant dims, leaving the ~128 learned
    ones (and their embeddings/weights) untouched
  - persist the init spec in the checkpoint (so eval/plot know the intended spectrum)
  - init-time self-check: rebuild histogram, assert hot-count ≈ target, assert tail mem < 200 MB

**Two routes:**
  - **(a) Surgical continuation** — from the current checkpoint, re-init dormant decays to the
    spread. One command, hours to signal. Expect a CE shock (embeddings were shaped under
    short-memory dynamics) — judge only after ~3 MB, like the tail shock.
  - **(b) Fresh from scratch** — clean, but discards ~54 MB of training. Only if (a) shows
    promise and we want the canonical run.

## Phase 3 — A/B the spread (overnight, ~8 h)

From one snapshot, `--data-seed` fixed, ~5–10 MB per arm, sequential:
  - Arm A: continuation, no spread
  - Arm B: continuation + spread

**Success criteria (expanded after the mini-AGI audit):**
  - B held-out CE (clean multi-slice mean) is no worse than A beyond measurement noise; out-of-domain is not worse
  - long-range/massed-domain probe is no worse than the no-spread control
  - decay GradSNR and actual parameter movement improve rather than merely sigma changing
  - state activity and eligibility use show that new long dimensions are actually used
  - reinitialized dimensions were dormant by multi-signal liveness, not merely small sigma
  - chat probe holds a topic across 1–2 sentences; filler collapse ("some/something/sad") softens
  - mechanism check: seeded long dims survive (don't decay back); medium→long flow up

**Reading the result:**
  - **B wins** ⇒ architecture wants a spectrum ⇒ next lever is capacity (Phase 4)
  - **B ties/loses** ⇒ the model genuinely wants few long dims ⇒ plateau-at-~30 B is itself a
    finding ⇒ bottleneck is capacity/architecture, not init

## Phase 4 — scale (only after mechanism + data trusted)

Order of operations:
  1. **Capacity:** dim 512→768, or layers 16→20 (4.5M → ~10M params). Cheapest real gain if
     Phase 3 says "wants more long dims". Use the clean ruler + chat probe to judge.
  2. **Long-dim budget:** raise hot-dim target if tail cost stays <15%/step.
  3. **Corpus:** test a mixed wikistories + narrative arm, but do not assume the model is data-limited
     or make a fixed 200–500 MB target. More bytes are useful only if TMT's learning curves and
     domain/memory probes improve; more bytes alone is not evidence.

## Risks / watch list

  - **Tail-shock analogue:** any decay re-init may spike CE then recover. Never judge before
    ~3 MB of training.
  - **Hot-dim blowup:** assert hot-count/memory caps in init; abort if tail > 200 MB.
  - **Contamination habit:** never eval on a file reachable by the training glob; eval.py
    refuses to run if it detects overlap.
  - **Overfitting the ruler:** always report the 3-file SE and the cross-domain number; a win
    inside one SE is not a win. Watch out-of-domain, not just in-domain.
  - **One-training-at-a-time:** the box can't run two B=1024 trainings without thrash. Keep
    ablations sequential or run one per night.
  - **User controls the trainer:** do not launch/stop training without explicit OK. Prepare
    commands, hand them over.
