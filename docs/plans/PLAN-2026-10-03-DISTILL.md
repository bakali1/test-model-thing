**Date:** 2026-10-03

**Frozen decision from the author:** teacher is a *small* open model —
`LiquidAI/LFM2.5-230M-**Base**` (not the instruct/RL sibling). The conversion is
**Marginalize-It**, never End-Of-Token, because the goal is a tokenizer-agnostic

for now**. The distillation corpus is generated by the teacher **in the ruler's
own register** (TinyStories-style children's prose).

## 0. Why this plan exists, in one paragraph

TMT has an implementation and a ruler but no demonstrated long memory, and its
standing blocker is **gradient SNR ≈ 0.05** for the whole 889,897-step run. The
paper we just read says two things that bear directly on this: (a) byte models
start worse and end higher, so TMT's compute budget is far left of the point
where the byte thesis pays; (b) **distillation beats cross-entropy at matched
compute**, and the teacher's *distribution* carries more information per byte
than its text does. So: give TMT a teacher, and measure it the way the paper
warns you must — on two rulers, never on CE alone.

---

## 1. The one hard number (storage)

Measured by gate 0 on the ruler's own text: **4.106 bytes/token**
(`data/eval/tinystories_valid.txt`, 100 kB window; 4.011 / 4.039 on the other two).

```
teacher dump, k=32:  32 x fp16 value + 32 x int32 index = 192 B / token
                    192 / 4.106                        = 46.8 B / training byte
 64 MB slice  ->  3.0 GB       256 MB slice -> 12.0 GB
```

Top-k is mandatory, and **k=32 is sufficient**: a k-sweep to the full 64 k
vocabulary moves retained prefix mass by 0.005 at byte depth 1 and 0.000 at
depth 2 (`RESULTS.md`, 2026-10-03). k=8 is too small (costs 5 points at depth 0).

Top-k is mandatory, and **under top-k neither MI nor EoT is exact** — so the
paper's headline EoT>MI gap (a full-vocabulary effect at 128k–152k vocab) is
not available to us anyway. We choose MI on the segmentation-transfer argument,
which is the reason that *does* survive truncation. `tools/teacher_table.py`
builds the table with **zero dependencies** so it can be verified anywhere.

## 2. Gate 0 — the token→byte contract  ✅ CLEARED

`tests/check_distill.py` (free, CPU, ~10 s) — **PASS, 2026-10-03**:

| check | result |
|---|---|
| exact byte reconstruction of all three ruler eval files | **byte-for-byte identical** |
| bytes/token | 4.153 / 4.059 / 4.058 |
| `tokenizer.decode()` lossiness | **791 ids** return U+FFFD for non-UTF-8 byte tokens (id 604 → `b'\xa1'`) — must never build the table with `decode()` |
| post-processor trap | default encoding **injects BOS**, the literal 15-byte string `<\|startoftext\|>`; 0 emissions with it disabled |
| `added_tokens` shadowing | **507 of 509** added ids also exist in the base BPE vocab; a base-vocab-only table maps them to the wrong bytes |

The last two rows were found *by this gate during development*, and the
shadowing one was a real bug in the first version of the table builder. Both are
now permanent assertions. **Do not use `tokenizer.decode()` anywhere in the
pipeline.**

## 3. Frozen configuration

| field | value |
|---|---|
| teacher | `LiquidAI/LFM2.5-230M-Base` — 229,693,184 params (14 layers: 8 short-conv + 6 GQA, hidden 1024, 32,768 ctx, 19 T tokens). **Measured: 0.6853 nats/byte** on `tinystories_valid` vs TMT's 1.1741–1.1902. |
| teacher dtype | **fp32** for the dump (see §6 gate 1b) |
| tokenizer | `tokenizer.json`, sha256 `df1d8d5ec5d0…`, recorded by the gate |
| conversion | Marginalize-It, top-k = 32, renormalized over the stored prefix-matching set |
| temperature | τ = 1 (no tempering) |
| α | 0.5 (half KD, half ground-truth CE) |
| loss | `α·KL(p_teacher_bytes ‖ p_student_bytes) + (1−α)·CE + variance hinge + embed-MSE + stop-MSE` (**unchanged**) |
| student | unchanged: dim 512, L16, B=1024, ring_k=18, tail on, fp32, TF32 off, lr 5e-4, seed 0 |
| dataset seed | 0 (identical byte stream to every other arm) |
| ruler | `.venv/bin/python tools/eval.py CKPT --slices 3 --bytes 20000 --xd-bytes 8000 --xd-files 4` |
| generation probe | `.venv/bin/python tools/chat_models.py` fixed prompt, seeds 0–5, 250 B |
| bar | **0.03 CE** on the held-out mean; byte/tokenization/register effects judged on the generation probe |

**Non-CE loss terms are deliberately untouched.** The variance hinge and
embed-MSE are what keep the JEPA latent objective (and therefore the memory
mechanism) alive; the teacher only informs the byte decoder.

## 4. Sequence

### Step 1 — ~~teacher-generated corpus~~ **WITHDRAWN 2026-10-03**

Built (`tools/gen_teacher_corpus.py`, `tools/calibrate_corpus.py`) and working,
then **withdrawn from the main experiment by measurement**: every generation
setting tested lands 0.11–0.23 below the real corpus on `unique_4gram`
(0.457–0.579 vs 0.687), with up to 12.5 % of stories flagged degenerate
(`RESULTS.md`, "CORRECTION to the distillation corpus plan"). A corpus that is
both differently-registered *and* less diverse would have made step 2 measure two
things at once.

It is also unnecessary: the real corpus is already local, already in the ruler's
register, and already decontaminated by construction — `wiki_tinystories_005.txt`
and `tinystories_valid.txt` were moved out of the training glob in Phase 0.1. And
local files have stable digests, which fixes the reproducibility gap that made
the 889,897-step CE rows unusable as a control.

Kept in the tree because it is the evidence, and because it is the right tool if
a synthetic arm is ever wanted at small scale. If used, it **must** be run with
the degeneracy summary reported and `tools/decontaminate.py` applied.

### Step 2 — ~~corpus-identity A/B~~ **WITHDRAWN 2026-10-03**

Withdrawn with step 1: without a comparable synthetic corpus there is nothing to
A/B, and the real corpus is already digest-verifiable. Replaced by a plain
**byte-matched CE control arm** over the same real corpus files (step 3), which
is the control this experiment actually needs.

### Step 3 — off-policy MI distillation — **THE EXPERIMENT** (~1.5 h T4 + 10 min dump)

Corpus: `data/wikipedia_clean/wikistories/wiki_tinystories_00{1..4}.txt`, with
each file's **sha256 recorded in RESULTS.md** so both arms are provably
byte-matched. Two arms, same seed 0, same `--data-seed 0`, same file order:

| arm | objective |
|---|---|
| A | CE only (existing path; must be bit-identical at α=0) |
| B | MI-KD, α = 0.5, τ = 1 |

Dump input is the same corpus, bucketed with `numpy_port.Runtime.make_streams`
at B=1024 so the targets align position-for-position with the trainer.

* **retained prefix mass** — the statistic most likely to silently corrupt the
  target. **Already measured on real ruler text** (`RESULTS.md`, 2026-10-03):

  | byte depth | mean mass | p05 | fraction < 0.5 |
  |---|---:|---:|---:|
  | 0 | 0.803 | 0.079 | 13 % |
  | 1 | 0.371 | 0.0003 | 64 % |
  | 2 | 0.320 | 0.0000 | 69 % |

  Truncation is **not** the cause (full-vocab sweep barely moves it). The cause is
  prefix matching: the teacher puts ~63 % of its mass at depth ≥1 on tokens that
  **end** at that position, which MI discards. So the MI target at depth ≥1 is the
  teacher *conditioned on not ending the token here*. Roughly half of all byte
  positions carry such a reconditioned target, which is a **bias**, not noise.
  Report the statistic per arm; the backoff gate applies where mass < 0.5.

### Step 4 — on-policy KD (later; needs a target bank)

Teacher labels **TMT's own rollouts**, replayed from a bank refreshed every
~2k steps (~5 % overhead, not 50 %). Must be **mixed** with real bytes: pure
on-policy amplifies existing modes (FS-N emitted 16 consecutive newlines).

## 5. Judge on two rulers, never CE alone

The paper's §6.6: at ~1.8e21 FLOPs all four byte models had *better* BPB and
*much worse* benchmark performance. An arm that wins held-out CE has not won.

**Gate for every KD arm:** ruler CE ≥ control **and** no regression in the
6-seed degeneracy metrics (max newline run, unique bytes, entropy) **and** no
`User:`/`Assistant:` leakage. A CE-only win is reported as a *partial* result
with the disagreement stated, in the spirit of the 600k caveat in `RESULTS.md`.

**Third ruler, added after the fidelity measurement:** **word-length drift**.
The MI bias (gauge 2) predicts that a KD arm learns tokens that run longer than
they do. Measure mean bytes per generated word and the premature-line-end rate
against the CE control. One pass over the 250-byte samples; CE cannot see this.

## 7. NOT tested / known gaps

* One teacher, one seed (0), one α (0.5), one τ (1). No sweep.
* The "does a stronger teacher help or hurt?" arm (Llama-3.2-1B) is **out of
  scope by decision**, so we will not know whether teacher capacity matters.
* Near-paraphrase contamination of generated text is **not** detectable by the
  0.6 verbatim-line filter.
* Teacher quality is **no longer an assumption**: measured at
  0.6853 nats/byte on `tinystories_valid` (100 kB window) versus TMT's
  1.1741–1.1902, i.e. **~0.49 nats/byte better**. The distillation premise holds
  at 230 M. Ruler settings differ from the CE rows above; treat as magnitude,
  not verdict.
* MI is **not** the exact conversion the paper describes, at any storage budget:
  the loss is structural (tokens that end mid-token), not truncation. See gauge 2.
* One teacher, one seed (0), one α (0.5), one τ (1). No sweep.
* The KD term's effect on gradient SNR (the standing blocker) is **unmeasured**.
  If SNR does not move, distillation has not addressed the actual problem and
  the role-specific-LR factorial remains the next experiment.

### 9b. CPU-only cost — MEASURED on this laptop (2026-10-03)

8 cores, 14 GB RAM (11 GB free), torch 4 threads. Rates measured, not estimated:

| workload | rate |
|---|---:|
| TMT training, numpy_port, B=1024 | 1.152 s/step = **889 B/s** |
| TMT training, B=64 | 143 ms/step = 447 B/s |
| teacher forward pass (scoring/dump) | 235 tok/s = **965 B/s** |
| teacher generation, batch 1 / 16 / 64 / 128 / 256 | 13.8 / 81 / 112 / 116 / 114 tok/s = **475 B/s, saturating at batch 64** |

Generation saturates because the reference `causal_conv1d` fallback is
compute-bound, not memory-bound; `causal_conv1d` cannot be installed here (pypi
DNS is unreachable from this box), so bigger batches do not help.

Cost of the plan on CPU alone, for a 64 MB slice:

| stage | CPU hours |
|---|---:|
| step 1 — generate the 64 MB corpus | **37.4** |
| step 2 — two CE arms | **40.0** |
| step 3 — dump 64 MB of MI targets | **18.4** |
| step 3 — KD arm (overhead **unmeasured**, est. +10–30 %) | **20–26** |
| rulers (4 × ~15 min) | 1.0 |
| **total** | **≈ 117–123 h ≈ 5 days** |

Two constraints make CPU-only worse than the hours suggest:

* **RAM.** A dump costs 46.8 B per training byte, and only ~11 GB is free, so the
  largest slice that fits is ~128 MB (6 GB) before sharding/streaming is built.
  A 256 MB slice needs 12 GB and will not fit.
* **No parallelism.** One 889 B/s process already saturates the 8 cores; two arms
  in parallel each get ~50 %, so wall clock does not improve.

**Verdict: CPU-only is ~5 days for the full 64 MB plan and is dominated by
teacher generation (37 h) plus the two CE control arms (40 h).** Use the T4 for
steps 1–3; keep the laptop for gates and rulers, which must run there anyway.

If CPU-only is forced anyway, the cheapest decisive run is a **16 MB slice with
arms A (CE) and B (KD) only**, skipping step 1 and step 2: ~30 h total, which
answers "does distillation help at all" in about a day. A reduced step-1 corpus
(8 MB, ~4.7 h) keeps the corpus-identity comparison alive at small scale.
