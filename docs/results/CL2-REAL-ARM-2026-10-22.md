## 0. THE HEADLINE: the first CL-2 arm never trained. Three silent no-ops.

The previous CL-2 arm (RESULTS.md §14) was reported as "a NULL for a budget
reason" — its held-out CE was 5.5463 against ln(256) = 5.5452, i.e. the model
was at UNIFORM, and the note said the arm had not started learning.

**That diagnosis was wrong. The arm could not have learned: nothing in it was
being updated.** Three independent bugs, each of which silently discards the
gradient, each of which leaves `loss.backward()` and `optimizer.step()`
perfectly happy:

1. **THE PARAMETER VIEWS WERE DETACHED LEAVES.** `gpu_port.GpuModel` builds
   its parameter views (`model.views`) while `theta` does **not** require grad;
   `tools/cl2_train.py:build_model` then calls `theta.requires_grad_(True)`.
   A view of a tensor that did not require grad is a *detached leaf*: after
   the base is switched it reports `requires_grad=True` but has **no
   `grad_fn`**, so the autograd engine accumulates **nothing** into it — and
   because the base's own `.grad` stays `None`, the gradient is **silently
   lost**. `backward()` raises nothing; the optimizer sees `p.grad is None`
   and skips the parameter. **The arm updated nothing, ever.**
   *Fix:* `tools/cl2_train.py:rebind_views()` re-creates the views **after**
   `theta.requires_grad_(True)`, so they are ordinary differentiable views
   (`grad_fn=ViewBackward0`) and the gradient lands in `theta.grad`.

2. **THE MEMORY HEAD'S PARAMETERS DID NOT REQUIRE GRAD.** `build_head()`
   allocated `Wm`/`bm` with `torch.empty`/`torch.zeros` and never called
   `requires_grad_(True)` — so the **memory loss had no trainable
   parameters at all**: the head stayed at its random initialisation and the
   "memory loss" was a constant. *Fix:* the head's tensors now require grad.

3. **THE CHECKPOINT SAVED THE GRADIENTS, NOT THE WEIGHTS.**
   `save_checkpoint` wrote `model.gviews` — the views into the **gradient**
   buffer `model.grads` — under the **parameter** names. So every "CL-2
   checkpoint" held the gradients, and loading one installed gradients as
   weights. *Fix:* `model.views` (the parameter views) are saved and loaded.

Two more defects in the trainer's self-test, which had **never been run**
(it crashed at its second check):

4. the gradient check read `model.embed.grad` (always `None` for a view) — it
   now reads the embed's slice of `theta.grad`;
5. the "state at the cue does not depend on the bytes after it" check
   captured the state at `L-1`, i.e. **after** the changed bytes, so it
   compared two different states and could only report a difference; it now
   captures at `L-4`.

**The self-test now has a gate that would have caught all of it**: after ONE
optimizer step the weights must MOVE (`|d theta| > 0` and `|d head| > 0`),
and the checkpoint must hold the weights and not the gradients
(`tools/cl2_train.py --selftest`, gates (iv) and (v)). It FAILS on the old
code and PASSES on the fixed code, on the MX150 as well as on the CPU.

**What this means for the programme:** the CL-2 arm was never run, so the
question "can the recurrent state be trained to hold a fact?" was never
asked. The arm below asks it for the first time.

## 1. THE ARM

```
tools/cl2_train.py --dim 512 --layers 16 --batch 512 --facts 4 --gap 32
    --alphabet 16 --half-min 2 --half-max 512 --wd 0 --wd-decay 0 --lr 5e-4
    --pre-steps 200 --phase1-steps 1000 --phase2-steps 1000
    --board-size 512 --board-seed-a 101 --board-seed-b 202 --board-seed-c 303
    --memory-alpha 0.25 --behaviour-weight 1.0 --seed 0
```

* the **P4** multi-scale half-life init (2–512 B), **P6** (no weight decay at
  all: `--wd 0 --wd-decay 0`), 16 layers of 512, batch 512 streams of 72 B;
* phases: **pre** = text-only CE (the general ability), **f1** = the
  PRE-STREAM facts (board A), **f2** = the STREAM facts (board B), with **no
  replay of A**;
* board **C** (seed 303) is never trained on: it is the held-out set.

### 2.1 ACQUIRE — PASS on the stream's facts (board B), NULL on unseen facts

The model's own trained head (a **parameter**, never refitted), gap 32:

| cell | per-byte | exact-4 | matched null | coverage | nuisance | verdict |
|---|---:|---:|---:|---:|---|---|
| **board B (the stream's facts)** | **0.9697** | **0.8906** | 0.0747 / 0.0020 | 1.00 | NULL (0.0557) | **SIGNAL → PASS** (≥ 0.50) |
| board C (never trained) | 0.1011 | 0.0000 | 0.0586 / 0.0000 | 1.00 | NULL (0.0586) | SIGNAL per-byte, exact-4 = 0 → **NULL on exact-4** |

gap 8: board B 0.9658/0.8730 (null 0.0605/0.0039).  gap 64: 0.9268/0.7559
(null 0.0781/0.0059).  **Prior comparison:** the global byte prior of the
training corpus predicts the payload targets at **0.0596/byte** and
**0.0000 exact-4**; the head is **16× the prior per byte** and 44 000× on
exact-4 (0.8906 vs 1.5e-05 chance).  **This is a real learn, not the prior**
— the FSP arm's failure (0.685 against a prior of 0.817) does not repeat.

**The copy control (the payload IN THE INPUT replaced by fresh random bytes,
the cue and the target unchanged): the head barely moves — 0.8940/0.6758
against the signal's 0.9697/0.8906.**  So the head's answer does **not** come
from the payload in the input: the association lives in the **head's
weights** (a key→payload table), not in the recurrent state.

### 2.2 RETAIN — FAIL, and it is not marginal

Board A (the pre-stream facts) replayed, read with the same head:

| gap | pre per-byte / exact-4 | post per-byte / exact-4 | ratio |
|---:|---:|---:|---:|
| 8 | 0.9663 / 0.8828 | 0.2139 / 0.0039 | 0.2213 / 0.0044 |
| 32 | 0.9644 / 0.8691 | 0.1978 / 0.0020 | **0.2051 / 0.0022** |
| 64 | 0.9390 / 0.8008 | 0.1504 / 0.0000 | 0.1602 / 0.0000 |

Threshold 0.90 → **FAIL**.  The pre-stream facts are **gone**: the stream
overwrote board A's 512 entries in the head's table.

(The **ridge** readout says 0.985 — and that is NOT retention: the ridge is
REFITTED on the cell's own rows, the board's 512 facts repeat across the 512
rows, so the train and test halves share facts and the readout re-learns the
mapping.  The head, a parameter, is the honest number.)

### 2.3 NO REGRESSION — FAIL, in both directions of the comparison

The ruler's CE cell (120 000 B over 6 slices, `mb.model_transfer_ce`):

| checkpoint | held-out CE (nats/B) |
|---|---:|
| base (end of the text-only phase) | 3.0695 ± 0.0218 |
| pre (end of the pre-stream phase) | 4.8854 ± 0.0805 |
| post (end of the stream phase) | **5.2037 ± 0.0201** |
| the unigram baseline | 5.5452 |

dCE(pre→post) = **+0.3183** nats/B (threshold ≤ 0.02) → **FAIL**;
dCE(base→post) = **+2.1342** nats/B → the fact training cost the model
**2.1 nats/B**, and the post-stream model is **within 0.34 nats of the
unigram baseline** — nearly as good as predicting a constant byte.

### 2.4 THE HELD-OUT CE TRAJECTORY (the trainer's own cell: 1×1000 B, NOT
interchangeable with the ruler's 120 000 B)

```
pre  0 5.9863 | 100 3.1128 | 200 2.9856
f1  100 8.4117 | 200 7.0351 | 300 7.6295 | 400 7.7234 | 500 7.4451 |
    600 6.6848 | 700 6.0694 | 800 5.9299 | 900 5.3815 | 1000 4.9274
f2  100 5.7354 | 200 5.1423 | 300 4.7095 | 400 4.3354 | 500 4.1937 |
    600 4.2113 | 700 4.0011 | 800 4.2896 | 900 4.3778 | 1000 4.5938
```

**The interference signature is a SHAPE, not an end point.**  In f1 the CE
*spikes* to 8.41 (the fact loss takes the output path) and then recovers to
4.93 while `ce_behav` falls 1.55 → 0.045.  In f2 the CE falls to 4.19 at
step 500 and then **rises** to 4.59 while `ce_behav` falls 0.054 → 0.018 and
the fact accuracies climb to 0.975/0.910.  **As the fact behaviour
improves, the text gets worse.**  The mechanism is specific: in
`train_step` the behavioural loss and the text CE are computed on the **SAME
logits**, so one output path must do both.

**The behavioural accuracy is a COPY, not a memory.**  The trainer's layout
puts the target bytes *in the input* right after the cue
(`seq[:, tgt0:tgt1] = pays[:, -1]`), so the model can emit them by copying.
`tools/cl2_memorization_test.py` measures it: the behavioural 0.9922/0.9688
collapses to **0.0742/0.0000** when the target tail is replaced, while the
head only falls to 0.8672/0.5938.  The 0.999/0.994 in the training log is a
copy of the input.

### 2.5 VERDICT AGAINST THE THREE PRE-REGISTERED THRESHOLDS

| number | threshold | measured | verdict |
|---|---|---|---|
| ACQUIRE (board B, d=32) | exact-4 ≥ 0.50 | 0.8906 (null 0.0020) | **PASS** |
| ACQUIRE (board C, never trained) | exact-4 ≥ 0.50 | 0.0000 | **NULL** (per-byte only 0.1011 vs 0.0586) |
| RETAIN (board A, post/pre) | ratio ≥ 0.90 | 0.2051 / 0.0022 | **FAIL** |
| NO REGRESSION (pre→post) | dCE ≤ 0.02 | +0.3183 nats/B | **FAIL** |
| NO REGRESSION (base→post) | — | +2.1342 nats/B | FAIL |

**What the arm actually did: it learned a 512-entry key→payload TABLE in the
head's weights.**  It did not learn to hold a fact in the recurrent state:
the copy control shows the head's answer survives the removal of the
payload from the input, and the state carries only a copy of the input's
payload (overwritten by the next write).  A table has one slot per fact, so
the stream's 512 facts overwrite the pre-stream's 512 — which is exactly the
RETAIN failure, and exactly why the capacity budget (§18) says the state is
1.06×–4.06× too small for one board.

## 3. THE FIXES TO THE TWO TOOLS

### 3.1 `tools/cl2_train.py` — the arm could not train until these were fixed

1. **`rebind_views()` (NEW).**  `GpuModel` builds its parameter views while
   `theta` does not require grad; `build_model` then sets
   `theta.requires_grad_(True)`.  A view of a non-requires-grad tensor is a
   **detached leaf**: it reports `requires_grad=True`, has **no `grad_fn`**,
   and the autograd engine accumulates **nothing** into it; the base's own
   `.grad` stays `None`, so the gradient is **silently lost**, `backward()`
   raises nothing, and the optimizer skips the parameter.  **The arm updated
   nothing.**  The views are now re-made *after* `requires_grad_(True)`.
2. **the memory head's parameters now require grad.**  `build_head()`
   allocated them with `torch.empty`/`torch.zeros` and never set
   `requires_grad` — the memory loss had **no trainable parameter**.
3. **the checkpoint now saves the WEIGHTS.**  `save_checkpoint` wrote
   `model.gviews` — the views into the **gradient** buffer — under the
   **parameter** names, so every CL-2 checkpoint held gradients and loading
   one installed gradients as weights.  It now saves/loads `model.views`.
4. **the self-test had never been run** and was broken in two places: the
   gradient check read `model.embed.grad` (always `None` for a view — it now
   reads the embed's slice of `theta.grad`), and the D4 check captured the
   state at `L-1`, i.e. **after** the bytes it had changed (now `L-4`).  Two
   gates were added: **(iv) the weights must MOVE after one optimizer step**
   and **(v) the checkpoint must hold the weights and not the gradients**.
   Both fail on the old code.
5. **the memory loss no longer runs in the text-only `pre` phase** (there the
   "target" is a constant zero, so the head was being trained to always
   predict 0).
6. **NEW `--wd-decay`** (P6): the decoupled decay on the **decay logits
   only**, default 0 (the P4/P6 setting: no decay at all).
7. **NEW the measurements the criterion needs**: the global **byte prior**
   of the training corpus, the head's and the behavioural accuracy at every
   log step and at every phase boundary, the **held-out CE trajectory**
   (`--ce-eval-every/--ce-eval-bytes/--ce-eval-slices/--ce-log`), the
   **held-out board C** (`--board-seed-c`), and all of it written into every
   checkpoint's `cl2_*` metadata (the boards, the alphabet, the facts, the
   gap, the prior, the memory eval) so the ruler needs no side channel.
8. two small bugs: the self-test's target tensor was left on the CPU while
   the logits were on the GPU (it only ran on the CPU before), and the
   self-test's scratch file went to `/tmp`, whose quota on the MX150 is
   exhausted (it now goes to the checkpoint directory).

### 3.2 `tools/cl_ruler.py` — the instrument, for a trained arm

1. **`--mode train` now RUNS.**  The refusal (whose five items CL-2 now
   supplies) is replaced by the real scoring: the three numbers, each with
   its own matched null, its class coverage, its nuisance control and a
   **PASS / FAIL / UNMEASURED** verdict.
2. **the arm's geometry is read from the CHECKPOINT by default**
   (`cl2_facts`, `cl2_gap`, `cl2_alphabet`), overridable with `--facts` /
   `--alphabet`.  The old default `--facts 64` probed a shape the arm never
   saw and put the RETAIN lag at 8·(facts−1)+d = 504+d, **four times** the
   128 B horizon.
3. **the horizon guard** (`HORIZON_B = 128`, from D5): a cell whose target
   sits beyond it is **UNMEASURED**, never a PASS.
4. **the RETAIN cell's lag is inside the horizon**: the pre-stream board is
   replayed in the *same* geometry as the ACQUIRE cell (the lag is d+4), so
   pre and post are the same rows and the same read.
5. **the cells are built from the CL-2 boards** (the trainer's `make_board`,
   imported): board B (the stream), board C (never trained), board A (the
   pre-stream replay).
6. **the primary readout is the model's OWN trained head** — a parameter,
   never refitted — and the ridge is reported beside it as the
   state-information number (a refit on the cell's own rows, with the
   board's facts repeated across rows, so it leaks; §2.2).
7. **TWO controls per recall cell**: (a) the **nuisance** — the target fact's
   key *and* payload replaced, so the target is absent from the state *and*
   from the weights; and (b) the **COPY CONTROL** — the payload **in the
   input** replaced, the cue and the target unchanged — which separates "the
   state holds the fact" from "the readout re-reads the input" and from "the
   head's weights hold the table".  Both are reported next to every cell.
8. **the prior comparison** (the FSP arm's test): the global byte prior of
   the training corpus is computed and reported next to every head cell.
9. **the cells use the TRAINER's gap** (real text for a fraction of the
   rows) and **the same gap array** for a cell and its controls, so the two
   differ in exactly one thing.
10. **`--ckpt-base`**: the dCE against the model's state **before any fact
    training** (the total episode damage) next to the pre-registered
    stream-vs-pre-stream dCE.  The two must not be confused.
11. the CE cell reports its bytes and its SE; the trainer's 1000-byte-slice
    CE is a **different measurement** and is not interchangeable with it.
